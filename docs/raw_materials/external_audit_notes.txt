任务 3：用 DICE 作为第一层自动质量筛查
老师明确说，如果数据集有 ground truth，就可以算 prediction 和 ground truth 的 DICE；如果 DICE 小于 50%，就挑出来放到 VLM 里比较哪个更好。
所以你的 verifier 应该这样设计：
DICE >= 0.80：直接接受
0.50 <= DICE < 0.80：标记为 uncertain，可选送 VLM
DICE < 0.50：必须进入 LabelCritic / VLM review
DICE = 0：严重错误，必须进入 review/update
你最终要展示的不是一个 case 的 DICE，而是 loop 后低质量 mask 数量是否减少。例如：
Loop	Checked masks	DICE < 0.5	VLM reviewed	Updated masks	Remaining uncertain
Loop 1	1000	180	120	95	60
Loop 2	1000	75	50	32	20
Loop 3	1000	25	15	8	5
老师想看到的是：经过几轮 loop，mask 质量变好，需要人工介入的数量越来越少。

任务 4：LabelCritic 必须读，并且要替换你现在简单的 3D-to-2D projection
老师明确指出你现在的 VLM label expert 只是把 3D CT/mask 简单压成 2D，这太粗糙。他让你去看 LabelCritic 的代码，因为里面已经写好了更合理的 projection，尤其是骨骼和软组织要分开处理，这样骨骼会更清楚。
我检查了 LabelCritic-main.zip，它的核心文件是：
CompareOrgan.py
ProjectDatasetFlex.py
ProjectDatasetFlex_single.py
RunAPI.py
RunAPI_single.py
ErrorDetector.py

它的 README 说明 LabelCritic 是一个用 LVLM 自动检查 AI-generated labels 的工具，可以在多个 annotation 候选之间选择更好的结果；医学 CT organ segmentation 场景中，它报告可以达到 96.5% 的 per-scan/per-class 高质量 annotation 选择准确率。
它的实际运行逻辑是：

→ VLM 输出 mask1 / mask2 / uncertain
→ CompareOrgan.py 写入 comparison_summary.log

python CompareOrgan.py \

  --mask1 Dataset/BDMAP_A0000001/predictions1 \

  --organ pancreas \
  --port 8000 \
  --log_file ./comparison_summary.log \
  --base_url "http://vllm_server_host"
所以你要做的不是重新发明一个 VLM reviewer，而是把 LabelCritic 封装成你项目里的一个 CLI tool：

  --organ pancreas \
  --output outputs/case_001/critic/pancreas_decision.json \
  --json

任务 8：把 mini annotation tool 和 RadThinking-style thinking pipeline 合成一个数据集
老师明确说：你现在有一个 mini annotation tool，又有一个 thinking pipeline，这两个东西可以合起来，变成一个更好的数据集。这个数据集不只是有 annotation/mask，还要有 reasoning 标注，也就是医生一步一步怎么看图像的过程。

9. RadThinking.pdf
RadThinking 是你的 reasoning trace / VQA dataset 方向依据。它不是用来跑 segmentation 的，而是告诉你最后数据应该怎么组织。
它的核心结构：
Foundation VQA：原子视觉问题
Single-step reasoning VQA：一条规则推理
Compositional VQA：多步医学推理
它的四步 trace：
Step 1: imaging observations
Step 2: temporal comparison
Step 3: clinical context
Step 4: conclusion
它还强调 cancer screening 不是简单 detection，而是观察、比较 prior scans、整合 clinical context、得出 pathology-confirmed conclusion。
用途：
1. 给你的 trace_builder 提供 schema；

3. 支持老师说的 VQA / mid-training / RL 方向；
